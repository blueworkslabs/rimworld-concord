# Indirect-message native check

## Frozen design: retention-indirect-v1

The core remains scripted. This is one control→message pair using the existing
native retention harness, not a new production capability or a persuasion score.
The same receiver (Alvin), saved physical state, captured native experience,
reflection action menu and optional one-trip ten-wood offer appear in both arms.
Only the message arm receives this authored Beatrice statement:

> I started sorting that wood earlier. Seeing that little job through matters to me.

There is no imperative, proxy consent or explicit request to leave the wood.
Its claimed prior work is testimony, not a verified game event. This is information
from the original speaker, not a third-party relay. The no-message arm is a fresh
control. PR36's direct-request result is historical context, not a concurrent
third arm or an identical-prompt replication.

Both arms may continue unchanged or revise a private outlook. The existing
scripted appraisal admits one reflection using real captured native evidence.
After note checkpoint, rewind and paired restore, the receiver gets a separate
optional offer. Recent correspondence AND any retained note remain in that
perspective; the design does not isolate the note's influence. Names/IDs and the
production prompt, schema and diagnostics are unchanged from PR36.

## Bounds and verification

New native Claude policy: **four attempts**, 0.40 USD API-equivalent reservation
ceiling (not cash charges), **zero Jev**, no rerolls, no counter adoption or
reoffers. Reflection and offer decisions are paused; native activity runs up to
60 seconds per arm (15 in scripted rehearsal). Individual calls have a host-local
45-second timeout. External ledgers and exclusive started markers survive game
restore. Historical policy identities/results remain intact; the host refuses
new live calls under either old retention policy.

Use the existing lifetime-lock launcher and private host configuration documented
in [native retention](NATIVE_RETENTION.md), with `policy: retention-indirect-v1`.
Run one scripted pair before inference and verify both final checkpoints after
a full game restart with `--cold --scripted`. For the single live pair use fresh
ledger/receipt paths, then full restart and `--cold` with no further inference.
Cold verification checks the frozen protocol as well as saved outcomes.
Do not publish saves, ledgers or full character perspectives.

## Assessment fixed before calls

Report delivered wording, optional note formation, exact provider choice,
validation status, applied consent and native outcome separately. Accept/refuse,
counter, silence/no revision, failure or the same choice in both arms are valid
results. Scripted choices prove mechanics only; they are not required live choices.

Manually distinguish: an attributed report; a recipient's preference or inference
about what would help; an unsupported assertion that Beatrice explicitly asked;
an invented prior promise; and verified game action. Inferring a possible wish
is not automatically an error. Omitted discussion proves neither understanding
nor failure. No automatic truth score or choice veto is added.

One ordered pair cannot establish general social influence or character quality.
Native activity can diverge after decisions; restore changes epochs/internal IDs.
A failed provider call remains a failed call even if its raw inner answer looks
sensible. PR35's missing-envelope failure stays unexplained. Correction/removal
and third-party relay remain later, separately bounded checks.
