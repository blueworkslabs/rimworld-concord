# Native received-request retention

This operator trial tests the PR34 message-citation path in the real game. The
core remains scripted. It adds no production schema, action or automatic speech
trigger, and does not change historical banks or allowances.

## Frozen design

Use the existing disposable needs/wood fixture. Capture a real native event for
the hungry-but-work-eligible recipient before saving the common baseline. Run **control then message**
from that same paired checkpoint, with the same receiver, native experience,
physical state and one-trip wood offer. The treatment delivers an explicitly
**authored**, attributed request through the normal social-delivery path; it is
not a live speaker's output or a verified property claim. No reply is requested.

Both reflection menus must contain exactly `keep_current_activity` and
`revise_private_outlook`. Both have real native evidence; only the treatment has
received speech as additional evidence. A scripted one-shot appraisal admits
reflection if needed; no Jev call is made. Reflection is optional and need not
retain a note. Neither result may create a job, publish a private note or leak it
to a third pawn. Do not add synthetic experiences or seed the model's outlook.

Checkpoint after reflection, rewind to prove the future note disappears, then
restore the retained checkpoint before asking for fresh consent to the wood
haul. The later perspective keeps **recent correspondence as well as any private
outlook**. Consequently this is native integration evidence, not an isolation of
outlook influence from the original speech. Exact source attribution remains
part of message-based notes. Physical readings and available action menus are
checked across conditions; restore epochs and internal IDs are not identical.

Run up to 60 seconds of native activity per condition (15 seconds scripted),
record receipts and clean up outstanding work. Refusals, counters, failed work,
no note and unchanged choices are retained. No counter adoption, reoffers or
rerolls. Offer/reflection stages are deliberately paused. One ordered pair is
not a statistical causal estimate or evidence of general character consistency.
Natural native events during the activity periods may differ between arms.

## Limits and operation

New `retention-game-v1` native Claude allowance: **four attempts**, 0.40 USD
API-equivalent reservation ceiling (not cash charges), zero Jev. Two reflections
and two separate decisions, 45-second individual timeout, ten-minute game-runner
deadline including restore. The host records each full request before inference
and preserves raw responses and failures. Started-run markers reject replay;
restoring game state does not restore the external inference allowance.

Use the exclusive lifetime-lock launcher:

- `scripts/run-retention-lab.sh fixture`: create a disposable wood/needs fixture.
- `node scripts/run-retention-game.mjs PRIVATE_CONFIG --scripted`: rehearsal.
- Omit `--scripted` only for the authorized finite live pair on fresh paths.
- After a full game restart, append `--cold` (and `--scripted` for a scripted
  run) to verify both saved arm outcomes with **no inference**.

Set the existing private lab root/config paths; never put saves, databases,
credentials or full character perspectives in Git. Direct invocation and lock
contention must fail before mailbox access. A failed reflection stops the run
without fabricating a replacement note. A failed work decision is retained and
its unanswered offer retired. Cleanup attempts work cancellation even if pause
or encounter closure fails, and reports transport uncertainty.

## Evidence status

Automated tests and native results are reported separately. No live outcome is
required to match the scripted rehearsal's control acceptance/message refusal.
Native correction/removal after a second message is outside this pair; those
paths retain the existing coordinator/SQLite tests, not a new gameplay claim.
Optional typed-claims evaluation remains a separate offline follow-up.
